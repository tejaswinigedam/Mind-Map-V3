# Agentic Mind Mapping System — V3

An AI-powered, interactive mind map generator built on a **4-skill agentic pipeline**. Enter any topic and the system reasons through intent, builds a semantically precise knowledge tree, lets you expand individual branches on demand, and answers contextual questions about any node — all in real-time via WebSocket.

Every branch label is a **specific named concept** generated by the model, never a generic template. The system supports arbitrary topics out of the box: from *"Quantum computing for finance"* to *"Dark psychology"* to *"Biohacking for women"* — no hardcoded domain trees.

### The 4 Skills

| Skill | Trigger | Input | Output |
|-------|---------|-------|--------|
| **IntentClarifierSkill** | Every new topic (+ answer submission) | `topic`, optional `priorAnswers[]` | `{ intent, depth, clarifications[], userGoal, confidence }` |
| **KnowledgeArchitectSkill** | After intent is resolved | `SkillIntentResult` | `{ root, children: SkillMapNode[] }` — full hierarchical tree |
| **ExplorationSkill** | On-demand: user clicks "Expand Node" | `nodeLabel`, `parentTopic`, `depth` | `{ newChildren: SkillMapNode[] }` |
| **NodeConversationSkill** | On-demand: user asks a question | `nodeLabel`, `parentTopic`, `question` | `{ answer: string }` |

**Semantic Depth Law** enforced at every level — every node label must be a specific named concept (theory, algorithm, mechanism, measurement) never a generic phrase like *"Advanced X"* or *"X Fundamentals"*.

## Setup & Running

### Prerequisites
- Node.js v20+
- A Google Gemini API key from [aistudio.google.com](https://aistudio.google.com/)

### 1. Install all dependencies
```bash
npm run install:all
```

### 2. Configure the API key
Edit `backend/.env`:
```env
GOOGLE_API_KEY=your_gemini_api_key_here
PORT=3001
```

> If no key is provided the system boots into offline simulation mode — returning empty stubs. A key is required for real map generation.

### 3. Start both servers
```bash
npm run dev
```

| Server | URL |
|--------|-----|
| Frontend | http://localhost:3000 |
| Backend WebSocket | ws://localhost:3001 |

## WebSocket Events

| Direction | Event | Payload |
|-----------|-------|---------|
| Client → Server | `START_WORKFLOW` | `{ topic: string }` |
| Client → Server | `SUBMIT_ANSWERS` | `{ answers: ClarifyingAnswer[] }` |
| Client → Server | `EXPAND_NODE` | `{ nodeId, nodeLabel, parentTopic, depth }` |
| Client → Server | `ASK_NODE_QUESTION` | `{ nodeId, nodeLabel, parentTopic, question }` |
| Server → Client | `STATE_UPDATE` | Full `OrchestratorState` (memory + status + logs) |
| Server → Client | `NODE_ANSWER` | `{ nodeId, question, answer }` |

## Model Chain

The system tries models in order, skipping to the next on quota (429) or not-found (404) errors:

```
gemini-2.5-flash-lite  →  gemini-2.5-flash  →  gemini-2.0-flash-lite  →  gemini-2.0-flash  →  gemini-flash-latest
```

Each model has its own independent free-tier quota bucket, so exhausting one does not block generation.
